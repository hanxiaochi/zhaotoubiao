# 安全与数据责任基线

- 不在源码、数据库迁移、示例数据、日志、构建产物或发布包中保存 API key。
- 上传文件限制类型和大小，使用服务端生成的存储键，计算 SHA-256。
- 所有写接口要求认证并进行权限判定；管理员之外的角色遵循最小权限。
- 审计日志只追加，不提供普通业务删除接口。
- AI 输出默认为“待复核”，不自动形成法律、评估、审计或投标终局结论。
- 备份必须同时覆盖数据库和对象存储，并进行恢复演练。
- 生产默认强制 TLS、安全 Cookie、Host 白名单、CSP、安全响应头和登录/上传/AI/写操作速率限制。
- 正式发布前必须在目标云环境再次执行 Brakeman、Bundler Audit、PostgreSQL 迁移、对象存储权限和恢复演练。
- 生产数据库账号不得授予应用对 `audit_events` 的 UPDATE/DELETE 权限；迁移账号与运行账号应分离。
# 2026-09-06 增量安全边界

所有原件通过当前用户的业务对象权限检查后下载，Active Storage 默认公开签名路由关闭（包括直接上传）。更新部署必须重启 Web 进程使此配置生效；旧签名 URL 失效是预期行为。私有 OSS/S3 仍为生产必要条件，不能把 Bucket 改为公开读取。

AI 写回需同时通过项目访问、审批角色、任务状态、业务状态和源数据指纹检查。无指纹历史任务只能拒绝或重新生成，不回填指纹冒充已验证旧来源。文件下载 no-store 不会收回用户之前合法下载到本地的副本。
