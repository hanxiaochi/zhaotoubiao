## 需求到改进项

| 老板需求 / 质量要求 | 对照后要求 | 当前证据与缺口 |
| --- | --- | --- |
| 企业资质和案例复用 | 资料有类别、单位、编号、有效期、停用状态与附件；过期资料不能新增引用 | LibraryEntry 页面、持久化与请求测试；专业资质真实性仍人工核验 |
| 投标评分点证据 | 引用保存资料版本、说明、原件标识、页码和引用人；修改来源不得回改已引用依据 | BidEvidence 快照和附件追加；评分点变更后提示重新核对 |
| 权限与数据隔离 | 功能权限不意味着可以读取所有项目；资料库查阅/管理权限分离 | 新增 library.view/manage；修复投标复核未核对项目访问权的问题 |
| AI 可信辅助 | 只向分析提供人工选择的来源快照，不自动遍历企业资料库；文档不是指令 | PromptBuilder 引入已关联快照；不生成自动资格认证结论 |
| 审批一致性 | 内容或证据变化后清除旧复核标记；重新人工确认 | 投标编辑及新增引用失效旧复核；并发/AI 写回仍需完整审计 |
| 文档安全 | 原件只通过权限检查后的下载入口，不因知道别的附件 ID 就能读取 | 已关闭默认 Active Storage 下载路由；业务鉴权、附件归属、撤权、no-store 与审计专项测试通过，生产对象存储仍待演练 |
| PC Web 可用性 | 桌面表格、横向筛选、详情分栏、明确失效/空状态 | 延用现有 PC 设计组件，不引入大型低代码前端 |
| 可读的人机复核 | 审核人先看逐项结果、来源与警告，再决定是否保留；原始响应可追溯 | 完整投标模拟建议表与折叠模型原文；前端预览与服务端批准复用同一安全校验，无效输出不能批准 |
